## 2. AE2 兼容：为什么是 `AECapabilities.ME_STORAGE`

**结论**：ME 存储总线读取的是**相邻方块的 `AECapabilities.ME_STORAGE` 方块能力**，因此本模组只需注册该能力即可；**不需要**网格节点（`IInWorldGridNodeHost`）、不需要频道与供电。

证据（AE2 19.2.17 字节码，`javap -c`）：

```
appeng.parts.storagebus.StorageBusPart 构造函数：
  new appeng/parts/PartAdjacentApi
  getstatic appeng/api/AECapabilities.ME_STORAGE : Lnet/neoforged/neoforge/capabilities/BlockCapability;
  invokespecial PartAdjacentApi.<init>:(Lappeng/parts/AEBasePart;Lnet/neoforged/neoforge/capabilities/BlockCapability;)V
  putfield adjacentStorageAccessor
```

即 `StorageBusPart` 的邻接查询 = `new PartAdjacentApi<>(this, AECapabilities.ME_STORAGE)`。`PartAdjacentApi` 内部用 `BlockCapabilityCache` 缓存该能力。

只允许 `import appeng.api.**`（沿用参考项目纪律）：本模组仅用 `AECapabilities`、`MEStorage`、`AEItemKey`、`AEKey`、`KeyCounter`、`Actionable`、`IActionSource`，均为公开 API。

### 抽取语义映射

| 需求 | 实现 |
| --- | --- |
| 报告所有池内物品各 N 个 | `MEStorage#getAvailableStacks(KeyCounter)` 对每个槽位模板 `out.add(AEItemKey, reportedAmount)` |
| 抽取需指定物品 | `MEStorage#extract(AEKey, long, Actionable, IActionSource)` 天然带 key；非 `AEItemKey` 或空请求一律返回 0 |
| 未指定物品则拒绝 | 通用侧 `IItemHandler#extractItem(slot, amount, simulate)` **恒返回 `ItemStack.EMPTY`**（该签名无法指定物品，故整体拒绝）；物品感知入口是自有的 `CreativePoolItemHandler#extractItemMatching` |
| 不接受输入 | `insert` 返回 0；`IItemHandler#insertItem` 原样退回、`isItemValid` 恒 false |

## 3. ProjectE 兼容：EMC 写入路径与上限

### 写入路径（用户命令同源）

ProjectE 的自定义 EMC 由 `moze_intel.projecte.config.CustomEMCParser` 管理，`/projecte setemc` 的实现是：

```java
CustomEMCParser.addToFile(toSet, emc);   // 合并进内存 currentEntries 并置 dirty
```

而 EMC 值在**每次数据包同步**时重算：`PECore#dataPackSync(OnDatapackSyncEvent)` →
`CustomEMCParser.init(registryAccess)`（读 `config/ProjectE/custom_emc.json`）→ `EMCMappingHandler.map(...)`。
**另有一条启动期计算路径**：`PECore#addReloadListeners(AddReloadListenerEvent)` 注册的重载监听器在**数据包加载阶段**
就完成一次 EMC 计算——专用服务器在 `Main` 主线程、服务器线程启动之前就加载完资源，因此这次计算**必然早于任何
服务器生命周期事件**（实测：`ServerAboutToStartEvent` 写入条目后，`ServerStartedEvent` 读回为 0）。

本模组因此在 `ServerAboutToStartEvent` 通过反射调用
`init(registries)` → `addToFile(NSSItem.createItem(item), value)` → `flush(registries)`，
把条目合并写进 ProjectE 自己的配置文件。好处：

- 条目已落盘，`/reload` 与重启后依然生效；
- 不覆盖玩家已有的自定义 EMC（走 ProjectE 自己的 read-merge-write）。

首次计算的时序与自愈（2026-09-27 实机验证）：启动期计算早于写入，所以**服务器刚启动时 EMC 映射暂不含本物品**；
生产环境无感——`OnDatapackSyncEvent` 在每个玩家加入时触发重算，玩家能查到 EMC 时条目必然已生效。
为了无玩家场景（如 gameTestServer）也能立即生效，本模组在 `ServerStartedEvent` 回读
`IEMCProxy.INSTANCE.getValue(stack)`，若不一致则**自行 post 一次 `OnDatapackSyncEvent(playerList, null)`**
（与 `/reload` 的群发路径完全相同，ProjectE 对 null 玩家的处理就是全量重算），随后再次回读并在日志确认。
`OnDatapackSyncEvent` 上另有幂等重申（覆盖配置文件被删/ProjectE 后加载的情形）。

### long 上限（重要）

- ProjectE 的物品 EMC 是 `Object2LongMap<ItemInfo>`（`EMCMappingHandler#getStoredEmcValue` 标注 `@Range(from=0,to=Long.MAX_VALUE)`），自定义 EMC 文件用 `nonNegativeLong()` 编码；
- Project Expansion 的 `SetEmcCMDMixin` 只把 `/emc set` 的提示替换为 `/px reloademc`，`SetEmcCMD` 的参数仍是 `LongArgumentType.longArg(0, Long.MAX_VALUE)`；其 BigInteger 出现在 `IEmcStorageBigInteger`（EMC 链接/继电器/收集器存储）与玩家 EMC 知识库，**不覆盖物品 EMC**。

因此：`9999999999999999999999`（≈1.0×10²²，超出 long 上限约 1084 倍）无法表示。按用户确认的口径，装 Project Expansion 时写入 `Long.MAX_VALUE`，并在 README/AGENTS 记录该限制。基础值 `999999999999999999` 完全在 long 范围内，正常写入。

## 4. 其他硬事实（本项目核对）

- `Slot.x` / `Slot.y` 在 1.21.1 是 **`public final`**：槽位坐标只能在构造时决定 → 布局常量集中在 `CreativeContainerLayout`，由 Menu 构造槽位、Screen 只画背景。
- `Block#appendHoverText(ItemStack, Item.TooltipContext, List<Component>, TooltipFlag)` 是 1.21.1 的签名（`TooltipContext` 是 `Item` 的内部类）。
- `Block#getRenderShape`/`getCloneItemStack(LevelReader,...)` 在 1.21.1 已过时（默认行为即所需）：不要重写，避免 `-Xlint:deprecation` 噪声。
- 自定义容器 GUI 三件套：`IMenuTypeExtension.create(IContainerFactory)`；`player.openMenu(provider, pos)` 自动写入 BlockPos；客户端 Screen 走 mod bus `RegisterMenuScreensEvent`；`AbstractContainerMenu` 没有 `getTitle()`。
- `@EventBusSubscriber` 的 `bus` 属性已废弃：客户端监听改为主类构造器内 `Dist.CLIENT` 守卫 + `modEventBus.addListener(CCClient::onRegisterMenuScreens)`，避免 dedicated server 加载客户端类。
- GameTest：`helper.setBlock/getBlockEntity` 收**结构局部坐标**，`helper.getLevel().getCapability(...)` 收**世界坐标**（`helper.absolutePos`）；`makeMockServerPlayerInLevel()` 生成在世界出生点，**必须传送**才能通过 `stillValid` 的 ≤8 格检查；该方法已过时但无替代。
- 服务端 `ResourceManager` 读不到 `assets/`：资源完整性守卫走 classpath 直读（`Class.getResourceAsStream`）。
- `data/creativecontainer/recipe/*.json` 用 1.21.1 的对象式 ingredient（`{"item": ...}`）与 `result: {"count": 1, "id": ...}`；掉落表在 `loot_table/blocks/`（单数）。
- 创造标签页条目必须**非 AIR 且 count == 1**：NeoForge 包装 `CreativeModeTab.Output` 会直接抛异常 → 有专门的 GameTest 重放同一条路径。

## 5. 风险与闸门

| 风险 | 闸门 / 现状 |
| --- | --- |
| ProjectE 的类名/方法签名随版本漂移 | 全部走反射 + 失败即降级（记 ERROR 日志、不影响加载）；写入失败不改变方块行为 |
| Project Expansion 未来真的支持 BigInteger 物品 EMC | 常量集中在 `ProjectEEmcBridge`；届时改成写 BigInteger 即可（一行 + 文档） |
| `EffectiveSide` 与 GUI 同步（数量 N 改了但客户端不刷新） | 数量走 `ContainerData`（`broadcastChanges` 每 tick 同步）+ BE `getUpdateTag` 镜像池内容 |
| 第三方创造标签页在服务端构建时抛异常 | `CreativeItemIndex.rebuild` 对每个 tab 单独 try-catch，坏 tab 只记日志并跳过 |
| 大量物品导致 GUI 卡顿 | 客户端静态索引一次构建 + 分页渲染（每页 45 项），搜索为前缀/子串匹配 id、命名空间与译名 |
| AE2 未安装时崩溃 | AE2 相关类（能力注册、ME 视图、AE2 测试支持类）**只在 AE2 存在时被加载**；编译期仅 `compileOnly` |

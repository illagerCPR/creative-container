# 00 — 创意方案与需求权威来源

> 项目：**Creative Container（创造模式容器）**
> 目标平台：Minecraft 1.21.1 / NeoForge 21.1.248
> 定位：**专供整合包**的模组——提供一个终局物品，作为整合包的终极目标。

本文件是需求的权威来源。改设计先改本文件，再动代码。

## 1. 一句话概念

一个可以被 ME 存储总线读取、带创造模式风格物品栏 GUI 的方块：它**不产出**资源，只是把「创造模式物品栏里的一切」变成一个可被自动化设备抽取的无限来源，并带一个荒谬的 EMC 值，让整合包作者可以把它放在进度树的终点。

## 2. 需求（原始，用户给定）

1. 新增**功能性方块**「创造模式容器」，具备 GUI，**GUI 近似创造模式物品栏**，提供**不限量**的物品。
2. 与其他模组方块的兼容性（以 AE2 为例）：
   - AE2 的「ME 存储总线」贴到本方块时，要向其**报告所有可在创造模式物品栏获取的物品 N 个**；
   - 该 **N 可在方块设置页面设置**，最大值 **2147483647**（`Integer.MAX_VALUE`）；
   - 其他方块请求从中抽取物品时，**若不指定物品则拒绝抽出**。
3. 与 ProjectE 的兼容性：
   - 本物品 EMC 值定为 **999,999,999,999,999,999**；
   - 若同时存在 Project Expansion，改为 **9,999,999,999,999,999,999,999**（该模组把 EMC 上限改为 BigInteger）。
4. 若需要且与本模组许可协议不冲突，可引入依赖；AE2 / ProjectE / Project Expansion **均非依赖关系，仅为联动关系**。

### v0.1.1 追加（2026-09-28，用户给定）

5. **删除默认配方**：模组不再随包分发任何合成配方，配方由整合包作者自行配置；方块仍可从创造标签页与命令获取。
6. **通用物流抽取**：走 `IItemHandler` 的物流管道（漏斗、Pipez、Create 等）能从本方块抽取物品；每个该方块的容器池独立。管道抽取的物品由玩家**在 GUI 内用特定键位指定**（悬停容器池槽位按键，再按一次取消），被指定的槽位在 GUI 中有**选定框**；未指定时整块拒绝抽取。AE2 ME 总线路径不受影响（见第 3 节口径）。
7. **拼音搜索**：物品搜索框支持拼音搜索（全拼与首字母），与 Just Enough Characters（通用拼音搜索）的体验一致但**不依赖它**——无论整合包是否装有 JEC，搜索框行为一致。
8. **UI 优化**：底色向 AE2 风格靠拢（浅色面板）；玩家物品栏与容器池上下互换（池在上、物品栏在下）并在右页水平居中。

## 3. 已与用户确认的设计口径（2026-09-27）

| 议题 | 结论 |
| --- | --- |
| 容器「库存」语义 | **虚拟无限池 + 槽位指定物品**：方块槽位数量可配置（默认 108，范围 9–4320），每槽一种物品且无限；外界（AE2/管道）只看到这些槽位里的物品，各按设定数量 N 报告。GUI 里的创造物品栏用于把物品放进槽位。 |
| 数量 N 的作用域 | **全局一个值 N**（1 … 2147483647），所有物品按同一 N 报告与抽出。 |
| ProjectE EMC 处理 | 无 Project Expansion：写入 **999,999,999,999,999,999**；有 Project Expansion：写入 **long 上限 9,223,372,036,854,775,807**，并在文档中记录原因（见第 5 节）。 |
| 通用管道抽取（v0.1.1） | 每个容器独立保存一个**管道出口槽**（`selectedSlot`，NBT 持久化 + 增量同步）：GUI 内悬停池槽按 **R**（默认，可改键）指定/取消，选定槽绘制选定框。`IItemHandler.extractItem(slot, …)` 仅在 `slot == selectedSlot` 时放行（池不减少），未指定时所有槽拒绝——「需要指定」的动作由 GUI 完成，管道侧零配置即可遍历抽取。移除/压缩池时出口跟随物品重新定位，物品被移除则回到未指定。 |
| AE2 与管道出口的关系 | **ME 侧不受管道出口限制**：ME 总线保持 v0.1.0 行为（总线 UI 里指定物品即可抽任意池内物品）；键位指定只约束 `IItemHandler` 通用物流路径。 |
| 拼音搜索（v0.1.1） | 内嵌 **PinIn**（JEC 同作者的拼音匹配库，MIT，经 JitPack 取得源码 vendor 进本模组、保留版权声明）：预建拼音索引支持全拼/首字母匹配显示名与注册 id；JEC 只是 JEI 搜索框扩展、无通用 API，故不联动、也不冲突——装不装 JEC 行为一致。 |
| 配方（v0.1.1） | **不随模组分发任何配方**；创造标签页条目与 `/give` 是获取途径，整合包作者用数据包自行配方。 |

## 4. 交付物

- 方块 `creativecontainer:creative_container` + 对应 BlockItem + 创造标签页 + 掉落表 + 贴图与中英文本地化。**配方不随模组分发**（v0.1.1 起），由整合包作者自行配置。
- 方块实体：虚拟无限池（槽位数量可配置）、可配置报告数量 N、持久化与客户端镜像。
- GUI：创造式物品栏（搜索 + 分页网格 + 抽取/入池）、玩家背包、容器池总览与数量输入框。
- 兼容层：
  - 通用：NeoForge `ItemHandler.BLOCK`（漏斗/管道等）；
  - AE2：`AECapabilities.ME_STORAGE`（ME 存储总线的读取路径，见 `docs/01`）；
  - ProjectE / Project Expansion：通过反射写入自定义 EMC（不引入编译期依赖）。
- GameTest 自动化守卫 + GitHub Actions CI。

## 5. 明确的不做（范围收敛）

- **不**新增维度、生物、多方块结构、任务书。
- **不**自动产出资源：容器只是「无限来源」，不主动注入网络（不给网络加无限 EMC 循环的自动入口；抽取行为完全由外部设备发起）。
- **不**做 Project Expansion 的 BigInteger 物品 EMC：ProjectE 的物品 EMC 存储为 `long`，Project Expansion 的 BigInteger 只覆盖 EMC *存储*（EMC 链接/继电器/收集器）与玩家知识库；其 `setemc` 命令 mixin 仅改写提示文案，参数仍是 `LongArgumentType(0, Long.MAX_VALUE)`。因此 1.0×10²² 无法落地，按第 3 节的结论写入 long 上限（详见 `docs/01` 的证据）。
- **不**做 ME 网络侧的无限注入设备（例如「给网络永久加无限存储」的元件）；本模组只提供「被抽取」的源。
